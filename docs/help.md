## 一、通知配置与脚本消息推送

### 1.1 脚本如何添加并触发通知？（青龙模式）

MiniCron 内置了 `scripts/notify.py` 桥接模块，**完全兼容青龙面板的调用习惯**。你无需在脚本中编写复杂的网络请求或传入 Bot Token，仅需导入并调用 `send(title, content)`：

```python
# 示例：sample_task.py
import os
from notify import send  # 直接导入内置通知函数

def main():
    # 模拟执行签到或抓取业务
    username = os.getenv("MY_USER", "测试用户")
    points_earned = 15
    
    # 组装纯净的业务结果
    title = "XX 平台每日签到成功"
    content = (
        f"✅ 签到操作完成\n"
        f"当前用户: {username}\n"
        f"本次获得积分: {points_earned}\n"
        f"当前总积分: 1250"
    )
    
    # 调用发送通知
    send(title, content)

if __name__ == "__main__":
    main()
```

> 💡 **通知呈现效果**：
> MiniCron 后台会自动捕获 `send()` 输出，向 Telegram 推送纯粹的 `【标题】+ 正文` 消息，并在文末附带轻量小字标注（`🕒 2026-09-22 08:00:00 · 任务名`），彻底剔除耗时、退出码、终端时间戳等一切机器参数噪音。

### 1.2 如何获取 Telegram Bot Token 与 Chat ID？

1. **获取 Bot Token**：
   * 打开 Telegram，搜索官方机器人 [@BotFather](https://t.me/BotFather)；
   * 发送 `/newbot`，按提示设置机器人的名称和用户名；
   * 创建成功后，@BotFather 会提供一段类似 `123456789:ABCdefGhIJKlmNoPQRsTUVwxyZ` 的 **HTTP API Token**。
2. **获取 Chat ID**：
   * **个人私聊**：向 [@userinfobot](https://t.me/userinfobot) 发送任意消息，它会回复你的纯数字 `Id`（例如 `987654321`）。
   * **群组/频道**：
     * 将你的 Bot 拉入群组或频道；
     * 将 [@userinfobot](https://t.me/userinfobot) 拉入群组，即可查看该群组的负数 ID（例如 `-1001234567890`）；
     * 频道也可以直接使用公开用户名（如 `@my_notify_channel`）。

### 1.3 四种任务通知策略如何选择？

在控制台顶部点击 **「⚙️ 设置中心」** -> **「🔔 通知与代理」**，可设置以下策略：

| 策略选项 | 行为表现 | 适用场景 |
| :--- | :--- | :--- |
| **`仅脚本主动通知 (青龙模式)`** <br>*(推荐默认)* | • 脚本调用 `send()` 时推送纯净业务通知；<br>• 普通成功任务保持静默；<br>• **脚本异常崩溃（非 0 退出）自动发送兜底故障告警**。 | **绝大多数日常签到、自动化脚本的最佳实践**，免去消息轰炸，有事才报。 |
| **`仅失败时通知`** | 仅当任务退出码非 0 或执行超时被强杀时发送故障卡片。 | 仅关心任务是否异常的监控场景。 |
| **`每次执行均通知`** | 无论成功失败均发送完整结果通知。 | 调试新脚本或需要确认每次触发执行的场景。 |
| **`完全关闭任务通知`** | 不推送任何定时任务的执行结果。 | 不需要接收任务推送时。 |

### 1.4 国内服务器网络穿透配置（防拦截）

由于 Telegram API (`api.telegram.org`) 在中国大陆境内无法直连，MiniCron 提供两种开箱即用的解决方案（在「设置中心」->「通知与代理」配置）：

* **方案 A：正向代理 (Proxy URL)**
  * 若服务器本地或内网运行有科学上网客户端（如 Clash、v2ray、xray 等），填入监听端口：
    * HTTP 代理：`http://127.0.0.1:7890`
    * SOCKS5 代理：`socks5://127.0.0.1:1080` 或 `socks5h://...`
* **方案 B：反向代理 Base URL（免客户端直连）**
  * 若服务器上没有代理客户端，可利用 Cloudflare Workers 或海外 VPS 搭建反向代理：
    * 在「反向代理 Base URL」填入自定义域名，如：`https://tg-proxy.yourdomain.com`；
    * 系统请求将自动转往该反代地址，完全无需本地运行代理软件。

### 1.5 系统安全告警分流配置（防暴破与凭据提醒）

MiniCron 将**系统关键操作告警**与**定时任务通知**在通道上进行了独立拆分：

* **安全专属 Chat ID**：
  * **使用场景**：通常建议将日常定时任务推送到群组或频道，而将**敏感安全告警推送到管理员个人私聊**。
  * **配置方式**：在「系统安全通知配置」中填入个人 Chat ID。若留空，则默认共用上方的任务 Chat ID。
* **细分开关**：
  * ⚠️ **登录失败告警**（默认开启）：输入错误密码时触发，自动记录来源 IP 与时间，有效监控暴力破解。
  * 🔐 **管理员密码修改**（默认开启）：密码被重置或修改后立即提醒。
  * 🔑 **登录成功提醒**（默认关闭）：自用频繁可关闭，防止频繁弹通知。
* **独立通道测试**：
  * 面板底部提供 **「🧪 测试任务通道」** 与 **「🛡️ 测试安全通道」** 两个按钮，可分别验证不同接收目标的连通性。

## 二、环境变量配置与使用

### 2.1 全局变量 vs 任务私有变量

MiniCron 支持两级环境变量管理，彻底替代在代码中硬编码密钥的危险做法：

1. **全局环境变量（「设置中心」->「全局环境变量」）**：
   * 适用于所有脚本通用的配置，例如通用的数据库连接串、公共 API Key、通用的 User-Agent 等。
   * 支持一键开关启用/禁用、前端掩码脱敏显示。
2. **任务私有环境变量（创建/编辑任务时的「任务专属环境变量」）**：
   * 适用于特定任务独有的配置，例如某个账号的 Cookie、Token、账号密码等。

> 📌 **多级覆盖优先级**：
> `任务专属私有变量` > `全局已启用变量` > `系统基础环境 (os.environ)`  
> 当任务专属变量与全局变量重名时，**以任务专属变量的值为准**。

---

### 2.2 脚本中如何读取环境变量？

在 Python 脚本中通过标准库 `os.getenv()` 读取：

```python
import os

# 读取变量，支持设置默认回退值
cookie = os.getenv("JD_COOKIE", "")
account_id = os.getenv("ACCOUNT_ID", "default_user")

if not cookie:
    print("❌ 未检测到 JD_COOKIE 环境变量，请在控制台配置！")
    exit(1)
```

## 三、Python 第三方依赖管理

### 3.1 报错 ModuleNotFoundError 如何解决？

当脚本中 `import requests` 或 `import bs4` 但环境未安装时，MiniCron 提供了智能诊断体验：

1. **智能一键安装**：
   * 打开任务执行日志，如果脚本因缺少依赖崩溃，日志顶部会自动浮现黄色告警横幅：
     `检测到缺失依赖: requests`；
   * 点击横幅中的 **「⚡ 一键安装 requests」** 按钮，系统将立即在后台为您自动拉取并安装。
2. **在设置中心主动管理**：
   * 随时前往「设置中心」->「Python 依赖管理」；
   * 输入包名（支持指定版本，如 `requests>=2.31.0` 或 `beautifulsoup4`），点击一键安装，并可在弹出窗口中查看实时安装进度日志。

---

### 3.2 国内镜像源加速

在安装依赖时，系统内置了 4 大源地址，可下拉一键切换：
* **清华大学源 (推荐国内)**：`https://pypi.tuna.tsinghua.edu.cn/simple`
* **阿里云源**：`https://mirrors.aliyun.com/pypi/simple/`
* **腾讯云源**：`https://mirrors.cloud.tencent.com/pypi/simple/`
* **官方源 (海外 VPS)**：`https://pypi.org/simple`

---

### 3.3 容器重启后依赖会丢失吗？

**不会！**  
通过 MiniCron 控制台安装的任何第三方模块，均会自动持久化落库至 SQLite 数据库的 `custom_packages` 表中。  
当您重启、升级或重新拉取 Docker 容器时，系统冷启动过程中会自动执行自愈逻辑（Auto-Recovery），自动扫描并静默补齐所有自定义安装的包，确保您的脚本环境始终健全。

## 四、Crontab 表达式编写速查

MiniCron 遵循标准的 **5 位 Crontab 规范**（分 时 日 月 周）。

### 4.1 5 位标准语法

```text
*    *    *    *    *
┬    ┬    ┬    ┬    ┬
│    │    │    │    └─ 星期 (0 - 6，0 代表星期日，或 1 - 7)
│    │    │    └─── 月份 (1 - 12)
│    │    └──────── 日 (1 - 31)
│    └───────────── 小时 (0 - 23)
└────────────────── 分钟 (0 - 59)
```

### 4.2 常见定时场景速查表

| 定时需求 | 表达式 | 描述 |
| :--- | :--- | :--- |
| 每天早上 8:30 | `30 8 * * *` | 最常用的日常签到触发时间 |
| 每天晚上 23:00 | `0 23 * * *` | 每日数据汇总或睡前签到 |
| 每隔 2 小时整点 | `0 */2 * * *` | 周期性数据抓取 |
| 每隔 30 分钟 | `*/30 * * * *` | 高频状态轮询 |
| 工作日早上 9:00 | `0 9 * * 1-5` | 周一至周五执行 |
| 每周一凌晨 3:00 | `0 3 * * 1` | 周度备份与维护 |
| 每月 1 号凌晨 1:00 | `0 1 1 * *` | 月度结转或月签 |

> 💡 **未来运行时间预演**：  
> 在 MiniCron 控制台输入或修改 Cron 表达式时，系统会**实时动态推算并在下方展示未来的 5 次触发运行时间**，方便您直观校验表达式是否正确。

## 五、安全沙箱与文件管理

### 5.1 脚本存放路径规范

* **统一工作目录**：所有脚本均必须存放在 MiniCron 项目的 `scripts/` 目录中。
* **严格沙箱防穿越**：系统在执行和编辑脚本时，会强制进行路径校验与解析。严禁任何形如 `../../etc/passwd` 的相对路径穿越，杜绝利用路径漏洞读取或覆盖宿主机关键文件。
* **文件管理方式**：
  * 在 Web 控制台点击「📝 脚本管理」：支持在线编写新建脚本、粘贴代码保存、上传本地 `.py` 文件，以及在内置编辑器中修改（支持 `Ctrl+S` / `Cmd+S` 保存与 Tab 4 空格缩进）。

### 5.2 生产环境安全建议

1. **修改默认管理员密码**：系统默认密码为 `admin123`，部署后请第一时间前往「设置中心」->「修改管理密码」更改为高强度强密码（系统采用 PBKDF2 100,000 次加盐哈希存储）。
2. **内网或反代部署**：推荐将 MiniCron 部署在局域网、内网或通过 Tailscale / WireGuard 等虚拟组网访问；如需暴露公网，建议前置 Nginx 配置 HTTPS 证书并设置反向代理。
