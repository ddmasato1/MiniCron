# MiniCron 产品需求规格说明书 (PRD)

---

## 1. 文档概述

* **项目名称**：MiniCron (轻量级 Python 定时任务管理与可视化调度系统)
* **文档版本**：v1.0.0
* **编写日期**：2026-09-19
* **面向对象**：个人开发者、自建小型 Linux 服务器 / NAS 用户

---

## 2. 背景与痛点分析

### 2.1 现状与痛点
许多用户在 Linux 服务器（如 1C1G/1C2G 规格的轻量云服务器或家用 NAS）上运行若干日常脚本（如各类平台每日签到、数据定时抓取、自动打卡通知等）。当前主流方案多采用**青龙面板**，但对于轻度用户存在显著痛点：

1. **资源开销过于庞大**：青龙包含完整的 Node.js + Python 混搭环境及庞大的依赖链，常驻内存往往高达 500MB~1.5GB，容易导致低配服务器 OOM。
2. **安全风险与攻击面广**：
   * 青龙面板历史上多次出现未授权访问漏洞、任意命令执行（RCE）漏洞以及依赖供应链污染。
   * 许多脚本需要暴露在公网通过 WebUI 管理，若权限机制设计不严或存在 Shell 注入拼接，极易被扫描器黑客利用入侵服务器。
3. **功能冗余繁杂**：普通用户仅需“定时跑几个 Python 脚本 + 看日志”，青龙的 Git 拉库、Cookie 互助池、动态装包等功能大部分闲置，反而增加了认知负荷与安全隐患。

### 2.2 核心建设目标
构建一个专为个人日常脚本设计的**极简、高安全、开箱即用**的可视化定时调度工具：
* **超低资源消耗**：单进程运行，空闲内存占用 < 50MB。
* **绝对安全防注入**：杜绝任意 Shell 字符串执行，限定执行沙箱目录，彻底根治 RCE 隐患。
* **单端口开箱即用**：后端兼顾 API 与前端静态单页面托管，无需独立部署 Nginx 或配置 Node.js 编译环境。

---

## 3. 用户角色与权限

* **单管理员模式 (Admin)**：
  * 系统面向个人及私有部署，采用简洁的高强度鉴权（密码/Token 认证）。
  * 未经认证的用户无法访问任何 API 或执行任何操作。
  * 默认支持设置 Web 访问密码或环境变量 `ADMIN_TOKEN`。

## 4. 详细功能需求 (FR)

### 4.1 任务管理 (Task Management)
* **FR-1.1 任务创建与编辑**：
  * **任务名称**：支持中英文别名（如“掘金每日签到”）。
  * **关联脚本**：从 `./scripts` 目录白名单中下拉选择目标 Python 脚本，支持子目录层级。
  * **定时规则 (Cron)**：支持标准的 Linux 5 字段 Crontab 表达式（如 `0 8 * * *` 表示每天 8 点）。
  * **规则预演**：输入 Cron 表达式后，界面实时解析并展示未来 5 次的预计触发时间点，防止配错时间。
  * **自定义环境变量**：支持为单个任务配置独立的 Key-Value 环境变量（如 `COOKIE=xxxx`、`PUSH_KEY=yyyy`），执行时安全注入子进程。
  * **超时设置**：支持设置任务最长运行时间（默认 300 秒），防止脚本挂起死锁。
  * **重入控制 (Coalesce)**：前一次触发尚未执行完毕时，自动跳过下一次调度，避免并发重入引发账号异常。
* **FR-1.2 任务状态与启停**：
  * 提供一键“启用 / 禁用”开关。禁用后保留配置但不触发定时执行。
  * 支持任务删除操作（删除任务配置及关联的执行历史索引，但**不**删除物理脚本文件）。
* **FR-1.3 管理员密码在线修改 (新增)**：
  * 支持在 Web 控制台在线修改管理密码，无需登入服务器修改配置文件或重启容器。
  * 采用行业标准的 PBKDF2-HMAC-SHA256 加盐哈希持久化存储于 SQLite `system_configs` 表中。
  * 原密码校验防未授权篡改，新密码强度检验（$\ge 6$ 位），向下兼容旧配置与环境变量。

### 4.2 调度与执行引擎 (Scheduler & Execution)
* **FR-2.1 自动定时触发**：
  * 基于 APScheduler，根据系统的本地时区精准触发。
  * 服务重启后，自动从 SQLite 重新加载所有已启用的任务，无缝继续调度。
* **FR-2.2 手动即时触发 (Run Now)**：
  * 任务列表中提供“立即运行”按钮。
  * 允许用户随时触发一次执行，便于调试脚本与验证逻辑。
* **FR-2.3 进程安全隔离执行器**：
  * 严格采用 `subprocess.Popen([sys.executable, script_abs_path])` 参数数组方式调用，**严禁使用 `shell=True`**。
  * 自动捕获 `stdout` 与 `stderr`，记录退出码（Exit Code: 0 表示成功，非 0 表示失败）。

### 4.3 任务执行日志与监控 (Logging & Monitoring)
* **FR-3.1 运行状态可视化**：
  * 任务列表直观显示：上次运行时间、上次运行状态（成功/失败/运行中）、下次预计运行时间、最近耗时。
* **FR-3.2 执行历史记录**：
  * 记录每次执行的：执行编号 (UUID)、开始时间、结束时间、耗时、状态码。
  * 支持清理或自动滚动清理历史记录（如默认保留最近 100 次记录）。
* **FR-3.3 实时日志与历史日志查看**：
  * 点击任务或执行记录可弹出日志抽屉。
  * 正在运行的任务支持实时轮询或流式输出追加。
  * 日志高亮显示（区分常规输出与异常堆栈）。
* **FR-3.4 智能缺失模块诊断与一键直达 (新增)**：
  * 当任务报错退出且日志中包含 `ModuleNotFoundError: No module named 'xxx'` 时，日志弹窗顶部自动弹出智能诊断告警横幅。
  * 提取缺失模块名称，提供「一键在线安装」快捷按钮，点击自动带入依赖管理面板秒级修复。

### 4.4 脚本文件管理 (Script Management)
* **FR-4.1 目录安全扫描**：
  * 自动扫描指定目录（`./scripts`）下的 `.py` 文件。
  * 路径合法性校验：防 `../` 路径穿越攻击，非白名单目录内的脚本拒绝注册。
* **FR-4.2 在线快速查看 (只读)**：
  * 提供轻量级的代码查看器，方便用户在界面上核对脚本内容。
* **FR-4.3 在线粘贴新建脚本**：
  * 支持直接在 Web 控制台大文本框中粘贴 Python 脚本源代码，自动补全 `.py` 后缀并落盘至 `scripts/` 目录。
* **FR-4.4 本地文件上传保存**：
  * 支持拖拽或点击选择本地 `.py` 脚本一键上传并自动保存至 `scripts/` 目录。
* **FR-4.5 关联任务防误删保护**：
  * 删除脚本时自动检查 SQLite 任务表；若脚本正被任意定时任务引用，系统自动阻断并提示关联任务名称，杜绝误操作。
* **FR-4.6 脚本在线代码编辑 (新增)**：
  * 支持在 Web 界面直接编辑现有 `.py` 脚本文件，提供暗色编程主题、行号与字数统计。
  * 编辑器内按 `Tab` 键智能插入 4 个空格缩进，防焦点跳出；支持 `Ctrl+S` / `Cmd+S` 快捷键瞬间保存。
  * 保存接口严格执行绝对路径与合法扩展名沙箱校验。

### 4.5 全局环境变量管理 (Environment Variables - 新增)
* **FR-5.1 全局变量持久化与 CRUD**：
  * 提供独立的「全局环境变量」管理中心，集中管理所有任务通用的配置（如通知 Token、数据库连接串、API 密钥等）。
  * 支持 Key-Value-Description 字段持久化保存于 SQLite `global_env_vars` 表中。
  * 键名严格符合操作系统环境变量命名规范（正则 `^[A-Za-z_][A-Za-z0-9_]*$`），并做唯一性排重。
* **FR-5.2 多级环境继承与覆盖机制**：
  * 优先级模型：`系统基础环境 (os.environ)` < `全局启用变量 (global_env_vars)` < `任务私有变量 (task.env_vars)`。
  * 当任务单独设置与全局同名的变量时，以任务专属变量值优先，实现高度灵活的私有化定制。
* **FR-5.3 安全脱敏与一键启停**：
  * Web 前端默认以掩码形式脱敏展示变量值（如 `abcd••••••••1234`），支持小眼睛明暗文切换查看与一键快速复制。
  * 支持单个变量无损一键「启用/禁用」开关切换，无需反复删除重新录入。
  * 子进程执行启动日志仅打印注入变量键名，绝不输出敏感值明文。

### 4.6 第三方模块依赖管理 (Package Management - 新增)
* **FR-6.1 环境依赖实时查看与检索**：
  * 异步调用 `pip list` 实时获取当前环境内已安装的所有第三方模块清单与精确版本号。
  * 支持按模块名称拼音或英文进行实时模糊过滤，区分系统核心依赖与用户自定义依赖。
* **FR-6.2 在线极速安装与镜像源切换**：
  * 支持用户在 Web 界面输入任意合规的 Python 模块名称（支持版本限定表达式，如 `requests>=2.31.0`）。
  * 内置清华大学源、阿里云源、腾讯云源、PyPI 官方源一键切换，解决离岸网络下载超时难题。
  * 采用 Server-Sent Events (SSE) 协议提供终端级实时流式输出，实时打印 pip 下载与构建日志。
  * 安装防并发锁保护：同一时刻仅允许一个包安装进程运行，防止环境锁冲突。
* **FR-6.3 系统核心运行库防误删保护**：
  * 内置核心系统库白名单（`fastapi`, `uvicorn`, `apscheduler`, `aiosqlite`, `pydantic` 等）。
  * 界面标记为「系统核心」并禁用卸载入口；后端 API 对核心库卸载请求进行硬拦截（HTTP 400）。
### 4.7 系统通知与网络代理 (Notifications & Proxy - 新增)
* **FR-7.1 Telegram 任务执行结果与业务内容推送**：
  * 任务执行完毕后，根据用户设定的策略自动格式化并推送 HTML 富文本执行报告至指定的 Telegram 对话/群组。
  * 报告包含：任务名称、脚本路径、执行结果（成功/失败/超时）、执行耗时、退出码、触发方式及完成时间。
  * **脚本业务内容提取**：自动清洗剥离 MiniCron 内部包裹标记与终端 ANSI 颜色代码，提取脚本实际产生的标准输出（如用户名、签到积分、业务结论等）；若内容过长，自动截取末尾核心日志（最多 35 行 / 2800 字符）并做 HTML 安全转义，在 Telegram `<pre>` 样式块中完整展示。
* **FR-7.2 双重网络代理穿透 (中国大陆境内服务器必备)**：
  * **正向网络代理 (Proxy URL)**：支持标准 `http://`、`https://` 及 `socks5://` 代理协议（如 `http://127.0.0.1:7890` 或 `socks5://127.0.0.1:1080`），借助宿主机或内网翻墙客户端畅通访问 Telegram API。
  * **自定义 API 反代地址 (Base URL)**：支持配置通过 Cloudflare Workers 或海外服务器自建的 Telegram API 反向代理域名（如 `https://tg.yourdomain.com`，替代官方 `https://api.telegram.org`），服务器无需安装任何代理客户端即可免代理直连。
* **FR-7.3 灵活通知触发策略与即时连通性测试**：
  * 支持三种触发策略：`ONLY_FAILURE`（仅失败/超时时通知 - 推荐免打扰）、`ALWAYS`（每次执行完毕均通知）、`OFF`（完全关闭）。
  * Web 控制台提供一键「🧪 发送测试通知」按钮，实时向指定 Telegram 推送测试卡片并反馈网络/代理连通状态。
* **FR-7.4 内置 `notify.py` 兼容垫片 (青龙面板脚本零修改)**：
  * 在 `scripts/` 目录内置标准 `notify.py` 模块，提供符合行业规范的 `send(title, content)` 函数。
  * 兼容所有形如 `from notify import send` 或 `import notify` 的常见签到脚本，调用时规范输出至标准输出并由 MiniCron 自动捕获与推送到 Telegram，彻底消除脚本内报缺少 `notify.py` 警告。
* **FR-7.5 一体化设置中心 (All-in-One Settings Center)**：
  * 将原顶栏平铺分散的通知设置、全局环境变量、依赖管理、修改密码等弹窗全面收敛至一体化「设置中心」侧边栏 Tab 面板，释放顶部操作空间，提高交互一致性。

## 5. 非功能需求 (NFR)

| 指标维度 | 需求标准 | 说明 |
| :--- | :--- | :--- |
| **内存占用** | 常驻内存 < 35MB | 纯 Python 轻量架构，无后台臃肿进程 |
| **启动性能** | 进程冷启动 < 1.5 秒 | 无重型框架预热开销 |
| **数据持久化** | SQLite 单文件存储 | 无外部数据库依赖，拷贝文件即完成备份 |
| **Docker 镜像体积** | 镜像体积 < 100MB (实测 98.9MB) | 基于 `python:3.11-alpine` 极致瘦身，内置 pysocks 代理驱动 |
| **部署便利性** | 单命令运行 / 极简 Docker | 提供 `docker compose up -d` 及本地 Conda/Python 启动脚本 |
| **离线友好** | 核心调度零外网强依赖 | 调度与界面运行不依赖外部 CDN（静态资源本地打包） |

## 6. 安全基线要求 (Security Baseline)

1. **防 Shell 注入**：所有进程派生均不得经由系统的 shell 解释器（无 `sh -c` / `bash -c`），参数不进行字符串拼接。
2. **防路径穿越 (Path Traversal)**：使用 `pathlib.Path.resolve()` 校验所有文件绝对路径，必须位于系统预设的 `SCRIPTS_DIR` 内部，否则直接抛出 403 异常；上传/粘贴/在线保存文件名自动净化。
3. **鉴权防护**：
   * 所有管理与执行 API 强制校验 Token。
   * 支持通过 Cookie / Header (`Authorization: Bearer <token>`) 双重传递。
   * 支持 Web 界面在线修改密码，哈希采用 PBKDF2-HMAC-SHA256（100,000 次加盐迭代）。
4. **依赖防破坏**：
   * 严密内置核心系统依赖白名单，杜绝在 Web 控制台误删 FastAPI、APScheduler 等基础环境。
5. **网络代理安全**：
   * 代理与 Token 仅由管理鉴权接口存取，Telegram Bot Token 留空时自动保留历史配置，防泄露。
6. **绑定机制**：
   * 默认配置文件中监听地址推荐为 `127.0.0.1`，引导用户配合反向代理或内部网络使用；如监听 `0.0.0.0`，系统在未配置高强度密钥时在启动时打印高危安全告警。
