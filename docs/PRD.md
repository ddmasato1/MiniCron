# MiniCron 产品需求规格说明书 (PRD)

---

## 1. 文档概述

* **项目名称**：MiniCron (轻量级 Python 定时任务管理与可视化调度系统)
* **文档版本**：v1.0.0
* **编写日期**：2026-09-19
* **面向对象**：个人开发者、自建小型 Linux 服务器 / NAS 用户

---

## 2. 背景与痛点分析

### 2.1 现状与痛点
许多用户在 Linux 服务器（如 1C1G/1C2G 规格的轻量云服务器或家用 NAS）上运行若干日常脚本（如各类平台每日签到、数据定时抓取、自动打卡通知等）。当前主流方案多采用**青龙面板**，但对于轻度用户存在显著痛点：

1. **资源开销过于庞大**：青龙包含完整的 Node.js + Python 混搭环境及庞大的依赖链，常驻内存往往高达 500MB~1.5GB，容易导致低配服务器 OOM。
2. **安全风险与攻击面广**：
   * 青龙面板历史上多次出现未授权访问漏洞、任意命令执行（RCE）漏洞以及依赖供应链污染。
   * 许多脚本需要暴露在公网通过 WebUI 管理，若权限机制设计不严或存在 Shell 注入拼接，极易被扫描器黑客利用入侵服务器。
3. **功能冗余繁杂**：普通用户仅需“定时跑几个 Python 脚本 + 看日志”，青龙的 Git 拉库、Cookie 互助池、动态装包等功能大部分闲置，反而增加了认知负荷与安全隐患。

### 2.2 核心建设目标
构建一个专为个人日常脚本设计的**极简、高安全、开箱即用**的可视化定时调度工具：
* **超低资源消耗**：单进程运行，空闲内存占用 < 50MB。
* **绝对安全防注入**：杜绝任意 Shell 字符串执行，限定执行沙箱目录，彻底根治 RCE 隐患。
* **单端口开箱即用**：后端兼顾 API 与前端静态单页面托管，无需独立部署 Nginx 或配置 Node.js 编译环境。

---

## 3. 用户角色与权限

* **单管理员模式 (Admin)**：
  * 系统面向个人及私有部署，采用简洁的高强度鉴权（密码/Token 认证）。
  * 未经认证的用户无法访问任何 API 或执行任何操作。
  * 默认支持设置 Web 访问密码或环境变量 `ADMIN_TOKEN`。

---

## 4. 详细功能需求 (FR)

### 4.1 任务管理 (Task Management)
* **FR-1.1 任务创建与编辑**：
  * **任务名称**：支持中英文别名（如“掘金每日签到”）。
  * **关联脚本**：从 `./scripts` 目录白名单中下拉选择目标 Python 脚本，支持子目录层级。
  * **定时规则 (Cron)**：支持标准的 Linux 5 字段 Crontab 表达式（如 `0 8 * * *` 表示每天 8 点）。
  * **规则预演**：输入 Cron 表达式后，界面实时解析并展示未来 5 次的预计触发时间点，防止配错时间。
  * **自定义环境变量**：支持为单个任务配置独立的 Key-Value 环境变量（如 `COOKIE=xxxx`、`PUSH_KEY=yyyy`），执行时安全注入子进程。
  * **超时设置**：支持设置任务最长运行时间（默认 300 秒），防止脚本挂起死锁。
  * **重入控制 (Coalesce)**：前一次触发尚未执行完毕时，自动跳过下一次调度，避免并发重入引发账号异常。
* **FR-1.2 任务状态与启停**：
  * 提供一键“启用 / 禁用”开关。禁用后保留配置但不触发定时执行。
  * 支持任务删除操作（删除任务配置及关联的执行历史索引，但**不**删除物理脚本文件）。

### 4.2 调度与执行引擎 (Scheduler & Execution)
* **FR-2.1 自动定时触发**：
  * 基于 APScheduler，根据系统的本地时区精准触发。
  * 服务重启后，自动从 SQLite 重新加载所有已启用的任务，无缝继续调度。
* **FR-2.2 手动即时触发 (Run Now)**：
  * 任务列表中提供“立即运行”按钮。
  * 允许用户随时触发一次执行，便于调试脚本与验证逻辑。
* **FR-2.3 进程安全隔离执行器**：
  * 严格采用 `subprocess.Popen([sys.executable, script_abs_path])` 参数数组方式调用，**严禁使用 `shell=True`**。
  * 自动捕获 `stdout` 与 `stderr`，记录退出码（Exit Code: 0 表示成功，非 0 表示失败）。

### 4.3 任务执行日志与监控 (Logging & Monitoring)
* **FR-3.1 运行状态可视化**：
  * 任务列表直观显示：上次运行时间、上次运行状态（成功/失败/运行中）、下次预计运行时间、最近耗时。
* **FR-3.2 执行历史记录**：
  * 记录每次执行的：执行编号 (UUID)、开始时间、结束时间、耗时、状态码。
  * 支持清理或自动滚动清理历史记录（如默认保留最近 100 次记录）。
* **FR-3.3 实时日志与历史日志查看**：
  * 点击任务或执行记录可弹出日志抽屉。
  * 正在运行的任务支持实时轮询或流式输出追加。
  * 日志高亮显示（区分常规输出与异常堆栈）。

### 4.4 脚本文件管理 (Script Management)
* **FR-4.1 目录安全扫描**：
  * 自动扫描指定目录（`./scripts`）下的 `.py` 文件。
  * 路径合法性校验：防 `../` 路径穿越攻击，非白名单目录内的脚本拒绝注册。
* **FR-4.2 在线快速查看 (只读/编辑)**：
  * 提供轻量级的代码查看器，方便用户在界面上核对脚本内容。

## 5. 非功能需求 (NFR)

| 指标维度 | 需求标准 | 说明 |
| :--- | :--- | :--- |
| **内存占用** | 常驻内存 < 50MB | 纯 Python 轻量架构，无后台臃肿进程 |
| **启动性能** | 进程冷启动 < 1.5 秒 | 无重型框架预热开销 |
| **数据持久化** | SQLite 单文件存储 | 无外部数据库依赖，拷贝文件即完成备份 |
| **部署便利性** | 单命令运行 / 极简 Docker | 提供 `pip install -r requirements.txt && python -m app.main` 及 Dockerfile |
| **离线友好** | 核心调度零外网强依赖 | 调度与界面运行不依赖外部 CDN（静态资源本地打包） |

## 6. 安全基线要求 (Security Baseline)

1. **防 Shell 注入**：所有进程派生均不得经由系统的 shell 解释器（无 `sh -c` / `bash -c`），参数不进行字符串拼接。
2. **防路径穿越 (Path Traversal)**：使用 `pathlib.Path.resolve()` 校验所有文件绝对路径，必须位于系统预设的 `SCRIPTS_DIR` 内部，否则直接抛出 403 异常。
3. **鉴权防护**：
   * 所有管理与执行 API 强制校验 Token。
   * 支持通过 Cookie / Header (`Authorization: Bearer <token>`) 双重传递。
4. **绑定机制**：
   * 默认配置文件中监听地址推荐为 `127.0.0.1`，引导用户配合反向代理或内部网络使用；如监听 `0.0.0.0`，系统在未配置高强度密钥时在启动时打印高危安全告警。

## 7. 演进路线规划 (Roadmap)

* **Phase 1 (基础架构与引擎)**：
  * 项目脚手架搭建、SQLite 数据表定义、安全执行器与 APScheduler 调度封装。
* **Phase 2 (API 与 Web 控制台)**：
  * RESTful API 实现、现代化单页面 Web UI（Vue 3 + Tailwind CSS）、日志查看器。
* **Phase 3 (运维与部署套件)**：
  * Dockerfile / docker-compose.yml、Linux Systemd 服务文件、通知推送扩展点（如 Bark / 微信 / Telegram）。
